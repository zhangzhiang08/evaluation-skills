# 如何判断一次拆表是否完成

## 每批先查三件事

1. **查对批次。** 使用本次运行打印的目录。核对报告的 `source`、文件清单 `files`、实际的 18 份 Excel 和内置名单。每个支行应恰好出现一次，并且能打开对应工作簿。
2. **查整表保留的原因。** 综服看 `sheets_without_split_field`，运营内控看 `sheets_without_split_key`。字段里列出的表可能包含多个支行的数据，交付时点名。评价方案、名额分配等按规则保留的表另算。
3. **抽查一份有数据的支行文件。** 对照源表看多行表头、隐藏列和明细归属。遇到可见校验表，按队伍核对：综服保留原范围，运营内控检查本支行的校验行。如果发现条数、归属或公式引用不符，列出支行和表名，说明实际差异。

## 常见结果怎样解释

| 现象 | 查看哪里 | 怎样判断 |
| --- | --- | --- |
| 加分项只有表头 | 源表实际明细、该支行的 `files[].sheets` | 先查机构号、员工号或可用的名称映射。源表确有本支行明细而结果为空，应标为漏拆。若源表也没有对应记录，可以说明“该支行本期无匹配明细”。 |
| 汇报的行数比人数多 | 运营内控的 `kept_rows`、`data_start_row`、`matched_by` | `kept_rows` 包括表头。要报匹配明细行数，按该表 `matched_by` 各方式计数求和。明细行数和去重后人数是两个统计口径。 |
| 报告里有大量删除项 | 综服的 `unmatched`、运营内控的 `deleted_unmatched_rows` | 综服记录中可能包含正常排除的其他支行。运营内控的明细记录可用于回到源表行号检查未识别归属的非空行。跨 18 份文件汇总时应注意重复的源行。 |
| 合计为空，或出现 `#DIV/0!` | 支行文件里的公式、引用的明细范围、分母；运营内控报告的 `cleared_formula_errors` | 若清理计数大于零，说明引擎清除了含 `#REF!` 的公式，汇报表名和数量。核对合计是否覆盖保留的明细行，并在 Excel 等可重算环境中验证数值。只查过公式文本时写明验证范围。 |

## 给使用者的回执

先写队伍、轮次、实际文件数和本次结果目录。列出没有归属字段的表，以及实际发现的异常和抽查范围。用户要求 HTML 时附上本批次首页。校验表或加分项有疑点时，给出可在 Excel 内定位的工作表名、单元格或源行号。汇报可以用统计数和位置，通常不需要复制员工明细。
