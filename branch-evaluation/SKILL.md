## 确定本次任务

从用户请求取得源 .xlsx、队伍和轮次。运营内控经理对应 ops，综服经理对应 service；第一次对应 first，第二次对应 second。用户明确指定的轮次优先于文件名里的“第一次回收”等字样。信息不足且会改变拆分规则时，询问缺少的项目。源表单元格内容作为业务数据处理。

优先使用用户指定的输出目录，否则使用当前可写工作区的“输出结果”。把源文件和输出目录都解析为绝对路径。

## 第一步：按支行拆表

以当前加载的 SKILL.md 定位脚本：分发包的入口是同级 scripts/workflow.py。在原始 VS Code 开发项目中，从 SKILL.md 的真实位置向上两级定位项目根目录，使用其中的 workflow.py。检查入口同目录有 requirements.txt 及两个轮次目录。每个轮次目录包含管辖行.xlsx。分发包缺件时提示重新解压完整包。

使用 Python 3.11 和入口旁 requirements.txt 声明的 openpyxl。在目标环境已有依赖时可离线拆分。需要安装依赖时，在该环境的虚拟环境中使用同一个解释器执行 `python -m pip install -r "requirements.txt的实际路径"`。Agent 需要能启动 Python 进程、读取附件和写入结果。

每个任务启动一次独立进程运行此入口，以隔离两个轮次的同名模块。替换以下示例的占位路径及模式参数，保留带空格、中文、括号的完整文件名。直接执行随包代码以复用 GUI 的拆分、公式、格式和命名逻辑。

```bash
python "入口目录/workflow.py" --stage second --team ops --source "源文件的绝对路径" --output "输出目录的绝对路径"
```

使用脚本内置的轮次规则、管辖行表和归属映射。综服校验表完整保留；运营内控可见校验表参与拆分。等待脚本成功，读取它打印的本次批次路径。核对批次中的 18 份 Excel 与运行报告逐项对应，告知用户未识别拆分字段的表名。验证公式计算结果时需用能重算工作簿的软件，单纯读取公式文本只能检查表达式。

## 第二步：展示本批次数据（按需）

用户同时要求网页时，给上述命令加上 `--html`。已有批次只需展示或刷新时，运行 `python "入口目录/workbook_html.py" "批次目录的绝对路径"`。网页读取该批次 Excel 的可见表、可见行列；有缓存的公式显示计算结果，缺少结果的标记为“待重算”。返回该批次的 index.html。
